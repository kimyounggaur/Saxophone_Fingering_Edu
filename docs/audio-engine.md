# SaxHands 오디오 엔진 — SaxTone 3.0 / 2.0

SaxHands의 기준음은 **외부 음원 파일을 내려받지 않는** 색소폰 모델링 합성음입니다. 오프라인 PWA에서도 알토·테너·소프라노의 서로 다른 음색과 정확한 기준 음정을 제공합니다. 엔진은 두 세대가 함께 들어 있습니다.

| | SaxTone 3.0 (`model`, 기본값) | SaxTone 2.0 (`classic`) |
| --- | --- | --- |
| 방식 | 음 하나를 순수 JS로 **미리 계산**해 `AudioBuffer`로 캐시하고 재생 | 재생할 때마다 Web Audio 노드 그래프(오실레이터·필터)를 실시간 구성 |
| 코드 | `lib/sax-model.ts`(렌더러) + `lib/sax-synth.ts`(캐시·재생) | `lib/sax-synth.ts`의 `playClassic` |
| 근거 | 실제 알토 색소폰 녹음을 분석해 맞춘 스펙트럼·시간·잡음 모델 (아래 "보정과 측정") | 손으로 맞춘 배음 감쇠 + 3단 포먼트 |
| 전환 | 설정 → 음색 엔진 | 같은 위치. 3.0 렌더링이 실패하면 **자동으로 2.0** |

3.0은 "실제 연주 녹음"이 아니라 **녹음을 측정해 만든 합성 모델**입니다. 설정 화면에도 그렇게 표시합니다. 음색이 좋은지에 대한 최종 판단은 사람의 귀가 필요하며, 이 문서의 수치는 "녹음과 얼마나 비슷한 신호인가"를 측정한 것이지 "듣기 좋다"를 보증하지 않습니다.

## 신호 구조 (3.0)

```text
renderSaxToneProgressive()  ── 순수 JS, 약 2ms 조각 단위, 결정적(seed)
  ├ 배음 합성: 최대 44배음, 체비셰프 점화식으로 sin(kθ) 생성
  │    배음 수준 = 기울기·음역·짝수배음 + 몸통 필터 E(f)      ← 알토 녹음에서 맞춘 값
  │    배음 k의 크기 ∝ envelope^(1 + 0.34·(k−1))              ← 리드 비선형: 고배음이 늦게 올라옴
  ├ 피치: 시작 스쿠프(−9~−21센트) → 안정, 지터 1.2센트, 드리프트 0.5센트, 지연 비브라토, 끝에서 처짐
  ├ 배음별 진폭 흔들림(측정값 1.4~9.5 %) + 비브라토에 따른 음량 숨쉬기
  ├ 호흡 노이즈: 몸통 대역 필터 → 로우패스 5.5kHz → 피치 주기에 동기(음과 섞여 들림)
  ├ 텅잉/공기 버스트: 어두운 대역, 약 60ms에 걸쳐 감쇠
  └ A-가중 라우드니스 정규화 + 다이내믹스 보정(세게 불어도 클리핑 없음)
            ↓ Float32Array → AudioBuffer (LRU 48개, 음마다 변형 2개)
BufferSource(±0.08 % 재생속도, ±0.25 dB) → 고역 차단 58Hz → 컴프레서 → dry/wet room → 음량
            (이후 마스터 체인은 2.0과 동일)
```

- **음역별 어택**: 저음(약 G3 이하)은 ≈60ms, 중음 ≈25ms, 고음 ≈20ms 상승(10–90 %). 악기마다 배율이 다릅니다.
- **악기 프로필**(`SAX_MODEL_PROFILES`): 알토·테너·소프라노가 기울기, 음역 의존, 짝수 배음, 몸통 필터 이동, 노이즈 중심, 비브라토 속도·깊이, 어택 배율을 따로 가집니다.
- **다이내믹스**: `intensity` 0.35–1. 세게 불수록 밝아지고(고배음이 더 커짐) 음량은 완만하게(진폭 ∝ drive^0.8) 커져서, 기본 설정에서는 렌더러 출력의 최대 파형이 0.76 이하이고 가장 센 조절(세기 1·밝기 1.5)에서도 약 0.93입니다. 마지막 단의 소프트 클립은 1.0을 넘지 않게 막는 안전장치일 뿐 평소에는 작동 구간에 들어가지 않습니다.
- **사용자 조절 인자**(`SaxToneControls`): `brightness`, `breath`, `attack`, `tongue`, `life`, `vibratoDepth`, `vibratoRate`, `vibratoDelay`, `release`. 앱 UI에는 노출하지 않고 엔진 옵션(`controls`)으로만 쓸 수 있습니다. 값은 안전 범위로 잘리고 NaN은 기본값이 됩니다.

### 성능과 끊김 방지

음 하나(1.42초, 44.1/48kHz) 렌더링은 데스크톱 크롬 기준 워밍업 뒤 **약 15–50ms**입니다. 페이지를 연 직후 첫 한두 번은 JIT 때문에 약 70–140ms까지 걸립니다(측정 환경은 서버 CPU의 헤드리스 크롬; 휴대전화는 2–3배 느릴 것으로 예상하지만 실측하지 않았습니다).

- 렌더러는 제너레이터로 쓰여 **64샘플 블록 96개(약 2ms) 단위로 양보**합니다. `prepare()`는 조각마다 `setTimeout(0)`으로 브라우저에 제어를 돌려줘서 손 애니메이션과 터치 입력을 막지 않습니다. 브라우저 실측: 8음 연속 자동 재생 중 50ms 이상 긴 작업 0건.
- 음을 고르면 앱이 `prepare()`로 다음 소리를 **애니메이션이 도는 동안** 미리 계산하고(자동 재생 켠 경우, 또는 이미 소리를 한 번 쓴 경우), 재생 직후에는 같은 음의 다른 변형을 백그라운드에서 준비합니다. `play()`가 먼저 호출되면 반쯤 끝난 작업을 이어서 마무리합니다.
- 첫 소리는 JIT 워밍업과 AudioContext 생성 때문에 느립니다. 브라우저 실측으로 첫 "듣기" 지연은 2.0이 약 80–105ms, 3.0이 약 125–140ms이고 두 번째부터는 둘 다 20–50ms입니다. 3.0 렌더러는 첫 터치 때 짧은 워밍업(`warmUpSaxModel`)을 조각 단위로 돌립니다.
- 음마다 변형 2개를 번갈아 재생하고 재생 속도·음량을 미세하게 흔들어, 같은 음을 반복해도 샘플 복제처럼 들리지 않게 합니다.
- 메모리: 렌더된 음 1개는 모노 Float32라서 ≈ 250–330KB(길이 1.42초/느린 속도 1.72초 × 44.1/48kHz), 캐시 최대 48개 ≈ 12–16MB입니다. 컨텍스트가 96kHz 이상으로 열리는 기기에서는 이 값이 두 배가 됩니다.

## 보정과 측정

### 레퍼런스와 한계 (중요)

| 용도 | 자료 | 비고 |
| --- | --- | --- |
| **주 레퍼런스(알토)** | `tonejs-instrument-saxophone-mp3` 1.1.2 (저장소 tonejs-instruments)의 색소폰 32음, 출처 표기상 Karoryfer | 샘플 CC BY 3.0. "무음 트리밍, 온/오프 램프, 음량 맞춤, 정규화, **노이즈 제거**, 필요 시 음정 보정"이 **이미 적용된 편집본**이며 악기 종류 표기는 "saxophone"뿐입니다. 음역(실음 C♯3–G5)이 알토와 일치해 알토로 간주했습니다. **단일 악기·단일 연주자** |
| 보조(알토·테너·소프라노) | MIDI.js 사운드폰트 `MusyngKite`, `FluidR3_GM`의 색소폰 음 | 샘플러 렌더이고 서로 크게 다릅니다(특히 테너). 테너·소프라노 보정의 유일한 근거라 **약한 증거**입니다 |

- 레퍼런스 음원은 **측정에만** 썼고 저장소·앱에 포함하지 않습니다. 라이선스는 각 저장소가 밝힌 대로 기록했으며(Karoryfer/tonejs-instruments CC BY 3.0, MusyngKite CC BY-SA 3.0, FluidR3_GM CC BY 3.0) 재배포할 일이 생기면 다시 확인해야 합니다.
- 위 편집 때문에 주 레퍼런스의 **어택 모양과 잡음 바닥은 원 녹음과 다를 수 있습니다**. 어택·노이즈 지표는 "편집된 알토 샘플과의 일치"입니다.
- 한 대의 악기만 보정했으므로 개체 차이(마우스피스·리드·연주자)는 모델에 없습니다. 알토 세 소스(실녹음·MusyngKite·FluidR3)끼리도 정적 배음 프로필이 3.8–6.1dB 다르고, 2.0의 오차(3.7dB)는 이 소스 간 차이와 같은 크기입니다. 반대로 3.0의 2.17dB는 **같은 녹음에 맞춰 조정한 값(in-sample)** 이라서 다른 알토 녹음에서도 이만큼 나온다는 뜻이 아닙니다. **그래서 3.0의 개선은 정적 스펙트럼 숫자보다, 2.0이 구조적으로 비어 있던 시간·확률적 요소(아래 표의 AM/FM/스커트/어택/음역별 음량)에서 찾는 것이 정직합니다.** 이 값들의 크기(%·센트)도 한 대의 녹음에서 잰 것이지만, "지속음의 진폭과 음정이 계속 미세하게 흔들린다"는 방향 자체는 연주 녹음 일반에서 알려진 성질이라 다른 녹음으로 바뀌어도 크게 틀어질 가능성이 낮다고 봅니다(이 문장은 측정이 아니라 판단입니다).

### 방법

같은 파이썬 분석을 실제 녹음과 합성 렌더에 똑같이 적용했습니다(`scripts/audio-calibration/`). 브라우저에서 2.0·3.0 엔진을 `OfflineAudioContext`로 렌더했고(마스터 볼륨 평활 때문에 0.3초 리드인), 비브라토는 끄고 비교했습니다.

1. 스펙트럼: 음마다 배음 30개의 크기를 재서 `기울기·음역항·짝수배음 + 반옥타브 매듭 필터 E(f)`를 최소제곱으로 맞춤(필터는 평균 0·기울기 0 제약, 교차검증). 음별 오프셋은 장애변수.
2. 시간: 10–90 % 상승, 90 %까지 시간, 오버슈트, 어택 초반(0–40ms)과 정상 구간의 스펙트럼 차이.
3. 미세 변동: 배음별 복소 복조로 진폭 변동(AM), 주파수 변동(FM), 반송파 주위 2–40Hz 잡음 스커트.
4. 잡음: 배음 사이 바닥(대역별), 어택 이후 시간별 HNR.
5. 음량: 음마다 A-가중 레벨의 음역별 편차.

읽는 법과 남은 차이:

- 2.0은 진폭·주파수 변동이 실제보다 훨씬 **정적**(AM 4배 이상 작고 FM 3배 큼)이고 어택 중 스펙트럼이 처음부터 완성돼 있으며 음역별 음량이 9dB 가까이 흔들립니다. 3.0은 이 부분들을 실제 범위로 맞췄습니다.
- 3.0은 고배음 주위 잡음 스커트가 실제보다 **2–6dB 깨끗하고**, 어택 중간(15–50ms)의 HNR이 실제보다 **2–5dB 높습니다**. 즉 실제 알토보다 조금 "정돈된" 소리입니다. 편집 샘플의 노이즈 제거 영향일 수도 있어 일부러 더 거칠게 맞추지 않았습니다.
- 3.0 상승 시간은 편집 샘플의 25ms에 맞췄습니다(온 램프 영향 가능).

### 테너·소프라노 (약한 증거)

SF2 두 세트가 테너에서 서로 3dB/옥타브 이상 다른 기울기를 요구해서 두 세트의 절충값을 썼습니다(`scripts/audio-calibration/fit_consensus.py`). 배음 프로필 오차(전력 가중 RMS 중앙값):

| 악기 | 레퍼런스 | 2.0 | 3.0 |
| --- | --- | --- | --- |
| 테너 | MusyngKite | 3.33 dB | 3.37 dB |
| 테너 | FluidR3 | 8.71 dB | **5.01 dB** |
| 소프라노 | MusyngKite | 2.60 dB | **2.41 dB** |
| 소프라노 | FluidR3 | 5.61 dB | **3.78 dB** |

테너는 MusyngKite 기준으로 2.0과 같은 수준이고 FluidR3 기준으로 크게 나아졌지만, **레퍼런스 자체가 약해서** 테너·소프라노의 "실제 같음"은 알토만큼 뒷받침되지 않습니다. 같은 실음 높이에서 테너가 알토보다 밝게 나오는 것은 SF2 두 세트의 경향(테너의 높은 음역)을 따른 결과이며, 실제 테너 녹음으로 다시 확인해야 합니다.

## 음정과 악기 처리

기준음 기준이 `실제로 들리는 실음`이면 기존 `concertMidi()` 결과를 합성 엔진에 전달합니다. `악보의 기보음`이면 written MIDI를 그대로 전달합니다. A4는 440Hz 12평균율이며 기존 이조 규칙은 다음과 같습니다.

| 악기 | 기보음에서 실음으로 | 실음 음역(MIDI) |
| --- | --- | --- |
| 소프라노 | −2반음 | 56–88 |
| 알토 | −9반음 | 49–80 |
| 테너 | −14반음 | 44–76 |

## 모바일·접근성 안전장치

- 소리가 꺼져 있으면(`소리 꺼짐`) AudioContext를 만들지 않습니다. 켜져 있으면 **페이지의 첫 제스처(탭·클릭·키)에서 컨텍스트를 만들고 깨웁니다**(Safari는 제스처 안에서 `resume()`을 불러야 하고, 자동 재생처럼 타이머로 넘어가는 음도 같은 컨텍스트를 쓰기 때문). 미리 계산(`prepare`)은 이미 엔진이 있을 때 또는 소리가 켜져 있을 때만 하고, 음량 0%이면 건너뜁니다.
- 자동 재생은 사용자의 실제 탭 안에서 먼저 컨텍스트를 깨운 뒤 애니메이션 지연을 적용합니다.
- 빠르게 음을 바꾸면 이전 예약 타이머를 취소하고, 동시에 진행하는 렌더 작업은 4개로 제한합니다.
- 연습 문제는 정답 공개 전 수동·자동 음색과 미리 계산을 모두 막아 음정 누설을 방지합니다. 정답을 보거나 답을 고른 뒤에는 정답 음이 납니다.
- 앱이 숨겨지거나 페이지를 떠나면 예약 음과 활성 보이스를 릴리스합니다. 동시 보이스는 2개까지입니다.
- 음량 0%는 최소 볼륨으로 치환하지 않고 실제 무음으로 처리합니다.
- 저장된 설정에 `toneEngine`이 없거나 알 수 없는 값이면 3.0으로 읽습니다. 렌더링이 실패하거나 NaN이 나오면 그 음만 2.0으로 재생합니다.
- 합성음은 실제 연주 녹음이 아님을 설정 화면에 명시합니다.

## 청음 랩 (A/B 청취 검수)

`scripts/audio-calibration/listening-lab/`는 두 엔진을 **귀로 비교하기 위한** 단일 HTML 페이지(약 80KB, 외부 요청·오디오 파일 없음)를 만듭니다. 앱의 `lib/sax-synth.ts`와 `lib/sax-model.ts`를 그대로 번들해 앱과 같은 마스터 체인(하이패스 → 컴프레서 → 리버브 → 마스터)을 거친 소리를 오프라인으로 렌더링하고 재생합니다.

- **같은 음량으로 비교**: 두 소리를 A-가중·무음 구간 제외 음량으로 0.05dB 이내까지 맞춥니다. 큰 쪽이 더 좋게 들리는 착시를 막기 위해서입니다. 최대 파형이 0.9를 넘으면 두 소리를 함께 줄여 맞춤을 유지합니다.
- **재생 중 즉시 전환**: 1·2 키 또는 버튼으로 같은 위치에서 20ms 크로스페이드로 바꿉니다.
- **블라인드 테스트**: 순서를 무작위로 섞고 어느 쪽이 어느 엔진인지 숨깁니다. "실제 색소폰 같음"과 "듣기 좋음"을 따로 집계하고, 답을 고르면 공개합니다. 라운드 중에는 3.0 조절을 잠급니다(3.0만 바뀌어 정체가 드러나므로).
- **분석 그림**: 두 소리가 같은 색 눈금을 쓰는 스펙트로그램과 배음 프로필. 알토는 실제 녹음에서 측정한 배음 값을 함께 그립니다(측정한 숫자만 있고 오디오는 들어 있지 않습니다).
- **3.0 음색 조절**: 밝기·숨소리·어택 등 9개 슬라이더로 3.0만 다시 렌더링해 비교합니다. 바꾼 값은 기록 JSON에 들어가므로 마음에 드는 값을 `lib/sax-model.ts` 상수나 앱 기본값에 반영할 수 있습니다.
- **기록 JSON**: 악기·재료·슬라이더·블라인드 집계·메모를 복사해 개발 대화에 붙여 넣을 수 있습니다.

빌드는 `node scripts/audio-calibration/listening-lab/build.mjs <출력 폴더>`입니다(esbuild는 이미 `node_modules`에 있습니다). 이 페이지는 판단을 대신하지 않고, 귀로 들은 결과를 모으는 도구입니다. 알토 외 악기에는 비교할 녹음 곡선이 없습니다.

## 운지가 바뀔 때 나는 소리

운지가 바뀔 때마다 **고른 악기(알토·테너·소프라노)의 SaxTone 3.0 소리가 기본으로 납니다.** 손이 움직이는 동안 음을 미리 계산하고(`prepare`), 손이 도착할 즈음(보통 430ms, 느리게 620ms, 동작 줄이기에서는 즉시) 재생합니다. 소리 높이는 설정의 기준음 기준에 따라 실음(기본)이나 기보음입니다. 새 음이 시작되면 앞 음은 짧은 페이드로 끊깁니다(단음 악기).

| 운지가 바뀌는 경로 | 소리 |
| --- | --- |
| 키패드, 방향키(←/→), 숫자키, `← 이전` | 난다 |
| 배우기: 모드 진입, 다음·이전 단계, 레슨 선택 | 난다 |
| 운지표에서 음 선택 | 난다 |
| `▶ 재생`(자동 진행) | 음마다 난다 |
| `♪ 음색 듣기` | 요청하면 항상 난다(소리를 꺼 둔 상태에서도) |
| 연습 문제가 나올 때 | **나지 않는다**(정답 음이 새지 않게) |
| 연습에서 `정답 보기`·답을 고른 직후 | 정답 음이 난다 |

끄고 켜기는 재생 조작 줄(데스크톱·태블릿은 오른쪽 패널의 탭 아래, 폰은 운지 화면 바로 아래)의 **소리 켜짐/꺼짐** 버튼과 설정의 "운지가 바뀔 때 소리"가 같은 값을 바꿉니다. 이 줄은 `← 이전`·`↻ 다시`·`♪ 음색 듣기`·`▶ 재생`·`소리 켜짐/꺼짐` 다섯 개를 한 줄에 같은 크기로 놓습니다. 연습 문제를 푸는 동안에는 이전·음색 듣기·재생이 비활성이 되고 "정답을 확인하면 소리가 납니다"라는 안내가 줄 아래에 나타납니다. 켤 때는 현재 음을 한 번 들려 줍니다(오디오를 깨우는 탭을 겸함). 꺼 둔 상태에서는 AudioContext를 만들지 않습니다.

### 저장된 설정의 이전 (`settingsRevision`)

앱은 모든 설정을 브라우저에 저장하므로, 기본값만 바꾸면 **이미 앱을 쓴 브라우저에는 옛 기본값("소리 꺼짐", 음량 18%)이 그대로 남습니다.** 그래서 저장본에 `settingsRevision`을 함께 저장하고, 불러올 때 `lib/settings-revision.ts`의 `upgradeSavedSettings`가 오래된 저장본을 한 번만 올립니다.

| 리비전 | 의미 |
| --- | --- |
| 1 (첫 릴리스) | 소리는 요청할 때만, 음량 18% |
| 2 | 운지가 바뀔 때 소리 켜짐, 기본 음량 50% |

1에서 올라올 때 소리는 켜짐으로 바뀌고, 음량은 **정확히 18%(슬라이더를 건드리지 않은 값)였던 경우에만** 50%로 바뀝니다. 악기·테마·사용자가 직접 정한 음량 등은 그대로이며, 이후 소리를 끄면 리비전 2로 저장되므로 꺼진 채로 유지됩니다. 새 기본값을 또 바꿀 때는 `SETTINGS_REVISION`을 올리고 같은 함수에 규칙을 더합니다.

### 기본 음량을 50%로 올린 이유 (측정)

소리가 저절로 나게 되면서 이전 기본값 18%가 너무 작다고 판단했습니다. 1.42초 음(알토, 실음 MIDI 50·58·70·82)을 앱과 같은 마스터 체인에 렌더링해 ffmpeg `ebur128`로 잰 통합 음량입니다(짧은 음이라 참고용 값).

| 음량 설정 | SaxTone 3.0 | SaxTone 2.0 |
| --- | --- | --- |
| 18% (이전 기본) | −26.7 ~ −25.8 LUFS | −27.6 ~ −22.4 LUFS |
| 40% | −21.3 ~ −20.4 LUFS | −22.2 ~ −17.0 LUFS |
| **50% (새 기본)** | **−19.8 ~ −18.9 LUFS** | −20.7 ~ −15.5 LUFS |
| 60% | −18.5 ~ −17.6 LUFS | −19.5 ~ −14.2 LUFS |

일반 음악은 −14 ~ −16 LUFS 근처이므로 18%는 같은 기기 음량에서 10dB 이상 작게 들립니다. 50%에서 3.0 음의 피크는 −7.5 ~ −13.5dBFS라 클리핑 여유가 충분하고, 음량 슬라이더로 더 키우거나 줄일 수 있습니다. 2.0은 높은 음에서 더 크게 나오는 경향이 있습니다(3.0만 음역별로 맞춰져 있습니다).

### 소리가 나지 않는 상황에 대한 대비

- **브라우저 자동재생 정책**: 위 첫 제스처 깨우기. 그래도 거부되면 "브라우저의 오디오 재생 허용 후 다시 눌러 주세요." 안내를 띄웁니다.
- **iPhone·iPad Safari의 무음 스위치**: Web Audio는 기본적으로 무음 스위치의 영향을 받습니다. 엔진을 만들 때 `navigator.audioSession.type = "playback"`을 지정해(`preferPlaybackAudioSession`) 영향을 줄입니다. Safari만 구현한 초안 API라서 지원하는 iOS 버전에서만 효과가 있고, **실제 기기에서는 확인하지 못했습니다.** 부작용으로 다른 앱에서 재생 중이던 음악이 멈출 수 있습니다.
- 음량 0%는 최소 볼륨으로 치환하지 않고 실제 무음입니다. 소리 켜짐 버튼이 켜져 있어도 이 경우에는 들리지 않습니다.

### 검증한 것

- 실제 Chromium(기본 자동재생 정책: 제스처 전에는 컨텍스트를 만들지 않음)에서 프로덕션 빌드를 열어 `AudioBufferSource` 시작과 출력 단계의 신호 레벨을 기록했습니다. 키패드·방향키·숫자키·`← 이전`·배우기·운지표·자동 재생 등 모든 경로에서 운지가 바뀐 뒤 0.45–0.7초 안에 음이 시작되고(컨텍스트 `running`, 출력 피크 −9dBFS), 소리를 끄면 침묵하며, 정지하면 멈춥니다.
- 악기별 음높이: 기보 G4에서 알토 233.1Hz(B♭3), 테너 174.7Hz(F3), 소프라노 349.5Hz(F4) — 실음과의 차이 ±2센트.
- 저장된 설정: 옛 저장본(리비전 없음, 꺼짐, 18%)은 켜짐·50%로 한 번 올라가고 악기·표기·테마는 유지, 사용자가 정한 음량(0·30% 등)은 유지, 리비전 2에서 끈 소리는 새로고침 뒤에도 꺼져 있음, 깨진 JSON·잘못된 값은 기본값(켜짐·50%)과 안내 토스트.
- 연습 문제: 문제가 나올 때는 침묵, `정답 보기`·답 선택 뒤 정답 음이 남, 다음 문제는 다시 침묵.
- 390px 폭에서 버튼이 화면 안에 들어오고 가로 스크롤이 없습니다.
- **하지 못한 것**: 사람의 귀로 듣는 판단(음색·음량이 적당한지)과 실제 휴대전화(특히 iOS 무음 스위치, 저가형 안드로이드)에서의 확인.

## 샘플 MP3 세트 (앱 기능이 아니라 한 번 만든 파일)

앱에는 MP3 저장 기능이 **없습니다.** 처음에는 운지 화면에 **⬇ MP3로 저장**(음 하나를 길이·세기·비브라토를 골라 저장)을 넣었다가, 파일이 필요한 쪽이 채팅에서 받는 편이 낫다는 판단으로 뺐습니다(저장소 기록의 `3b1282e`·`25f11d7`에 구현과 테스트가 남아 있습니다). 합성음이 필요하면 그 파이프라인으로 만든 파일을 따로 받습니다.

한 번 만든 세트는 알토·테너·소프라노 × 쓰기음 33개(B♭3–F♯6, F♯6은 High F♯ 키가 있는 악기만 운지 가능) = 99개 파일, 음당 3초 + 방 울림 0.5초, 세기 보통, 비브라토 있음, 256kbps CBR·44.1kHz·스테레오(ID3 태그에 악기·실음·운지)입니다. 파일 이름은 `NN_saxtone3_<악기>_fingering-<기보음>_pitch-<실음>_3s_mid_vib.mp3`(NN은 낮은 운지부터 01–33)이고 ZIP 안의 `00_README.txt`에 목록이 있습니다.

### 만드는 순서 (그때의 파이프라인)

1. `OfflineAudioContext(2ch, 44.1kHz)`에 **앱과 같은 `SaxSynthEngine`**(`mode: "model"`)을 올려 같은 음 캐시·마스터 체인(하이패스 → 컴프레서 → 룸 리버브)으로 렌더링합니다. 3.0이 아니라 2.0으로 조용히 대체되면 파일을 만들지 않습니다(`play()`가 실제 사용한 엔진을 돌려줍니다). 엔진의 `startAt`·`prefetch`·`maxNoteSeconds` 옵션과 오프라인 컨텍스트 지원은 이 용도로 만든 것이며 앱에는 남겨 두었습니다.
2. 음은 0.3초 뒤에 시작시키고, 음 시작 지점부터 `음 길이 + 0.5초 잔향`만 잘라 2ms 페이드인·40ms 페이드아웃을 겁니다.
3. 음량은 앱의 음량 설정과 무관하게 **고정**(엔진 음량 0.88)합니다. 파일마다 따로 키우지 않으므로 보정된 음별 상대 음량이 유지되고, 피크가 −1dBFS를 넘는 경우에만 전체를 줄입니다.
4. LAME의 JavaScript 이식(`@breezystack/lamejs`, LGPL-3.0)으로 256kbps CBR MP3를 만들고 UTF-16 ID3v2.3 태그를 붙였습니다. **앱에는 더 이상 이 라이브러리가 들어 있지 않습니다.**

### 세기(`intensity`) 옵션이 실제로 하는 일 (측정)

SaxTone 3.0은 음별 음량을 고르게 맞추도록 보정되어 있어, **세기는 음량이 아니라 음색의 밝기와 힘**을 바꿉니다. 같은 음(알토 기보 G4)을 비브라토 없이 3초로 렌더링해 분석한 값입니다.

| 세기 | 평균 음량(RMS) | 스펙트럼 중심 | 1kHz 이상 에너지 |
| --- | --- | --- | --- |
| 약하게 | -11.5dBFS | 470Hz | 5% |
| 보통 | -11.3dBFS | 642Hz | 14% |
| 세게 | -12.1dBFS | 958Hz | 31% |

33음 × 3악기를 세 세기로 렌더링한 297개의 중앙값도 같은 경향입니다(음량 지표 중앙값 -17.96 / -16.38 / -15.83dB, 세게의 최대 피크 -1.48dBFS, 피크 때문에 줄인 파일 0개). "약하게"가 실제로 작은 소리가 되길 원하면 세기별 이득을 따로 정해야 하며, 그것은 귀로 판단할 일입니다.

### 만든 세트를 확인한 것

- 99개 파일을 `ffprobe`·`ffmpeg`로 하나씩 확인했습니다: 코덱 mp3·44.1kHz·스테레오·256kbps, 길이 3.5초대, ID3 제목(악기·실음·운지), 앞 4ms·뒤 20ms 무음, 피크 −2.5 ~ −10.5dBFS(클리핑 없음), 기본음은 실음과 최대 2.4센트(평균 0.9센트) 차이, 통합 음량은 악기별 0.4–1.2LU 안에서 고름(알토 −12.5 ~ −11.3, 테너 −12.0 ~ −11.6, 소프라노 −12.3 ~ −11.4 LUFS).
- 합성 PCM과 디코드한 MP3를 맞춰 보면 SNR 43–52dB입니다(인코딩 왜곡은 음색 판단에 영향이 없는 수준).
- **파일 앞에 약 25ms의 무음이 붙습니다.** MP3 인코더·디코더 지연 때문에 길이는 3.5초가 아니라 3.527초이고, 소리는 파일 시작에서 약 31ms 지점부터 들립니다. 99개 모두 Xing/Info 헤더가 없어 플레이어가 이 지연을 잘라내지 못합니다. 한 음씩 듣는 데는 영향이 없지만, 끊김 없는 반복 재생이나 이어 붙이기에서는 25ms 틈이 생깁니다.
- 합성음이므로 실제 연주 녹음이 아닙니다. 알토 외 악기의 "실제 같음"이 약하다는 한계(위 보정 절)도 그대로입니다. 주관적 음색 판단은 별도 청취 검수가 필요합니다.

## 자동 검증

- 청음 랩으로 모은 청취 검수 결과(기록 JSON)를 반영한 상수 조정(특히 노이즈량·어택 질감·고음 밝기)

## SaxTone 2.0 신호 구조 (classic)

```text
악기·음역별 36배음 PeriodicWave
  → 리드 소프트 새추레이션
  → 3단 관 공명 포먼트 EQ
  → 음역 추적 로우패스
                         ┐
필터링된 호흡 노이즈 ───┼→ 클릭 방지 ADSR → DC 차단 → 컴프레서 → dry/wet room → 음량
키 터치 트랜지언트 ─────┘

5.0–5.5Hz 지연 비브라토 + 저속 미세 드리프트 → carrier detune
```

- 알토·테너·소프라노마다 배음 감쇠, 짝수 배음 비율, 3개 공명점, 밝기, 호흡량, 비브라토가 다릅니다.
- 시작 시 작은 피치 스쿠프와 키 접촉음을 넣고, 약 0.4초 뒤 비브라토가 자연스럽게 증가합니다.
- 최대 두 음만 동시에 유지합니다. 세 번째 음은 가장 오래된 음을 짧게 릴리스하여 클릭 없이 교체합니다.
- 마스터 컴프레서와 짧은 스테레오 룸 응답으로 모바일 스피커에서도 피크와 거친 고역을 억제합니다. 이 마스터 체인은 3.0도 그대로 씁니다.
- 모든 노이즈와 룸 응답은 기기 샘플레이트에 맞춰 한 번만 생성해 재사용합니다.
